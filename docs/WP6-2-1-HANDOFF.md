# WP6.2.1 — Remaining Effort quick entry

Implemented on `feature/wp6-progress-tracking`, starting from accepted WP6.2 commit
`b13638bf1171bd781b8aaaabb543233e3d446579`. The worktree was clean before editing.
Starting regression passed 300 tests, lint, typecheck and build. Main and the
`v1.0-pre-progress` tag remain protected and unchanged. The implementation commit
is the commit containing this handoff; its exact SHA is reported in the completion
message and available with `git rev-parse feature/wp6-progress-tracking`.

## Delivered refinement

- Tasks & Schedule has a **Remaining Effort** column beside Total hours. Known
  values include `h`; unknown is a dash with an Edit affordance and accessible
  Unknown text. Explicit zero is `0 h`.
- Clicking Edit opens a compact decimal input and selects the current number.
  Enter saves and restores trigger focus. Tab/Shift+Tab saves and advances to the
  next/previous available control. Escape and pointer Cancel restore the prior
  value. Pointer Save is available. Valid changed values commit on external blur;
  unchanged values close without writing or making a saved plan dirty.
- Invalid Enter/Tab/blur attempts retain the draft and accessible error without
  changing the stored estimate. Tab after a failed commit keeps usable input
  focus. Blank deliberately means unknown/null; it never becomes zero.
- Selecting a Gantt bar shows a compact task summary below the plotted timeline,
  with Remaining Effort quick edit, actual effort, estimated effort at completion
  and baseline effort variance. Inputs are outside the bars. Task Details retains
  its existing estimate form and work log.
- All three entry points use the same accepted `workTracking.remainingHours`
  state. Quick entry reuses WP6.2 `parseEffort(text, true)` and validated work
  updates. Actuals and comparison summaries update immediately; work sessions,
  baseline data and planned scheduling do not change.
- Quick-edit drafts participate in unsaved/replace safeguards and block conflicting
  edits. An invalid selected-chart draft can be resumed after selecting another
  task. Task identity is the permanent task ID throughout sort/reorder/selection.
- The existing table scroll contains a wider table rather than compressing names,
  IDs, dates or actions. Reviews at 1440px, 780px and 600px verify readable columns
  and no horizontal page overflow. A scoped positioning rule keeps hidden
  accessibility text inside its scroll container.

No new persistence format, domain model, remaining-estimate semantics or work-log
workflow was introduced. **Project format remains 3** and workTracking version
remains 1. WP5/WP6.1 imports, backups, explicit migration and local/JSON round trips
are unchanged. No statuses, percentages, finish-date forecasts or progress graphics
were added. WP6.3 and later remain deferred pending owner acceptance.

## Owner checks — A01–A10

Open `http://localhost:5173/`. Save/export your real plan before testing replacement
workflows. A task with an 8 h baseline and 6 h actual makes the comparison easy.

1. **A01 Fast path:** in Workspace, scroll to Tasks & Schedule and edit Remaining
   Effort directly. No bottom Work Log interaction is required.
2. **A02 Keyboard:** try Enter, Tab, Shift+Tab, Escape and outside blur. Try pointer
   Save/Cancel too. Existing text selects automatically and focus remains usable.
3. **A03 Unknown/zero:** enter 0 and verify `0 h`; deliberately clear the input and
   commit to restore the unknown dash. Escape must preserve the prior value.
4. **A04 Validation:** try `-1`, `NaN`, `Infinity`, nonnumeric text and three decimal
   places. The prior estimate remains; errors and draft stay accessible. Cancel
   restores it and clears the pending-edit Save restriction.
5. **A05 Dual access:** set the value in the table, select the task's Gantt bar and
   check the compact summary. Edit there and verify table and Task Details match.
   The original Task Details estimate form also updates both quick displays.
6. **A06 Comparison:** 6 h actual + 5 h remaining gives 11 h total and +3 h variance
   against the 8 h baseline. Change remaining to 2 h: total 8 h, variance 0 h,
   actual still 6 h.
7. **A07 Scheduling:** compare bar positions, planned dates, predecessors, calendar
   and critical path before/after edits. Switch expanded/compressed and scales;
   only effort values change, not scheduling or chart geometry.
8. **A08 Identity:** sort, return to Manual Order, drag/reorder and switch selected
   bars. Values stay with their original task IDs. Try an invalid chart draft,
   select another task, then Resume remaining edit to recover it.
9. **A09 Persistence:** Save/reopen, export/import and verify both null and zero.
   Confirm all work sessions and baseline fields persist. Existing WP5/WP6.1
   files still open using their existing compatibility/backup workflow.
10. **A10 Regression/layout:** inspect desktop/narrow views, table horizontal scroll,
    chart-first layout, dependency picker, inline fields, work logs, Gantt modes
    and Network controls. The full automated/browser suites pass as recorded above.

Ready for owner testing. Formal acceptance is pending; WP6.3 has not been started.
