## Thirty/forty tasks, accessibility and performance

Use [30-task](../../../tests/fixtures/wp71/student-30-prepared.json) and
[40-task](../../../tests/fixtures/wp71/student-40-performance.json) disposable
sources, then add controlled diamond/long-chain variants. Future browser tests
freeze meetingNov6 and explicit PA/FF contexts, run at1440 and600px. Assert
queue uniqueness/topological order, every changed/unresolved task reachable,
no horizontal page overflow, bounded rendered rows, no lost focus or page
errors and no Save/render loop. Record timings/long tasks without a blanket
zero-long-task guarantee; classroom-device acceptance is a separate measured gate.

Keyboard procedure: open completion from table and selected chart; Tab/Shift+Tab
through one labelled panel; Space chooses radio/checks; Enter only advances the
intended action. Back/Next focus the named task/step heading; an error summary
links its exact date/reason input. Forty tasks do not spawn forty modal stacks.
Escape/Close on dirty state offers Keep reviewing/Discard, keeps draft or
discards all as chosen, then restores the original trigger on final close.

Screen-reader procedure (record actual reader/browser/version after approval):
verify task ID/step, Actual versus Planned labels, date-only qualification,
disabled-advance reason, Unresolved explanation and error associations are
announced; concise polite recompute announcement avoids reading the entire
graph. All footer actions remain reachable at narrow size/high zoom. Manual
reader/owner review is required; automated focus checks are not that review.

First-slice acceptance excludes new UI/storage feature claims. Later public
activation is blocked until its relevant production-adapter, compatibility,
editing, accessibility and owner gates pass. See [IMPLEMENTATION-SEQUENCE](IMPLEMENTATION-SEQUENCE.md).
