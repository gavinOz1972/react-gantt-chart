# Proposed bounded next scopes - not started

These are reviewable options, **not approved work packages or an automatic
sequence**. Owner authorization must name the selected scope and prerequisites.
No new official WP number is assigned. The minimum route to a legacy pilot is
decision/qualification work; it does not require building every R07 feature.

| Proposal | Scope / dependency | Acceptance and stop |
| --- | --- | --- |
| P-A: owner/release gate closure | Review RR-01, R07 F04/F08 and release scope; record exact reviewed SHA and independent dispositions. Documentation only. | No inferred signatures; open conditions stay explicit; owner chooses legacy pilot, R07-integrated release or further stabilization. Stop before implementation/deployment. |
| P-B: student-platform qualification | After declaring course workflow/devices, run one representative semester plan through create/B/edit/dependencies/progress/forecast/save/reload/export/import/recovery; verify keyboard and required assistive technology. | Preserve real files, use copies; record hardware/browser/workload, failures and usability observations. Owner determines acceptable limits. No formula or UI redesign in the qualification scope; report demonstrated defects separately. |
| P-C: dependency triage | Address RR-04 with actual advisory paths/exposure; evaluate compatible maintained versions in isolation. | If update separately authorized, exact lockfile diff plus full checks and browser regressions; otherwise explicit bounded risk acceptance. No npm audit fix/major downgrade inferred. Stop for review. |
| P-D: narrow normal-consumer parity contracts | Depends on accepted R07 direction. Select **one** consumer and relevant WP7.4.6 gaps; define guidance, facts/origin, work detail or Actual Start precision as needed. | Typed validated source boundary, Unknown/Partial preserved and independent old/new goldens. Do not change formulas just to obtain matches. Keep full S/legacy persistence, default flags and other consumers unchanged; stop before broad integration. |
| P-E: private complete `/2` codec qualification | Depends on explicit F04/F08 decisions and exact field/integrity/migration contracts. Private unused codec, strict raw parsing, full semantic/link validation, opaque B, full D and preserved-source copy-upgrade. | Independent vectors plus negative/malformed/linked lifecycle/retirement/closure cases; reject without altering source/B/accepted head; complete round trips and measured full cost. No public writer/format migration/provider activation; owner review before integration. |
| P-F: physical provider/capacity qualification | Depends on requirements/provider choice and accepted codec/cost boundary. Select one provider, one platform and workload; include qualified higher-cap/recovery path before portable-only growth acceptance. | Atomic closure/B/history/counter/D/receipt publication, stale ref, quota/crash, exact retry/OutcomeUnknown, namespace isolation, pinned reads, cancellation, realistic lifetime/memory and reopen/export evidence. Unsupported gates stay explicit. No cloud service or DBMS chosen by this proposal. |
| P-G: first lifecycle/report vertical slice | Depends on qualified data/consumer/provider boundaries and a separately named UI scope. Choose one retirement/restore or report flow; do not silently implement all reporting. | Retained IDs/values and first B, full common-source successor closure, one outcome per ID, no stale review acceptance, accessible actions/Unknown/Partial, compatible complete export. No named snapshots, arbitrary replay or WP8 authorization inferred. |

P-D/P-E/P-F/P-G are necessary only for their affected R07 claims. P-B may expose
a smaller concrete runtime correction; if so, reproduce and isolate it before
proposing a fix. No broad refactor, formula rewrite, new health state, calendar
remaining deduction, mandatory work log, baseline rewrite or historical-data
fabrication is an acceptable shortcut.
